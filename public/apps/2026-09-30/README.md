# 1日1アプリ — 最終章 / 2026-09-30

365日間に作ったアプリが、現実の道・壁・建築を侵食した3Dアーカイブの基盤です。Vite + React + TypeScript + Three.js + React Three Fiber + drei。物理演算、影、ポストプロセスは使用しません。

2025-10-01〜2026-09-29の実アプリ364件を apps.json に反映済みです。公開サイトのタイトル・URL・初期画面キャプチャを使っています。9/30のアーカイブ自身は未登録のため、件数は364です。元の18件のサンプルは apps.sample.json に保存しています。

## 開発・公開

このディレクトリで `npm ci` → `npm run dev`。表示先は `/apps/2026-09-30/`。

`npm run build` で型チェックとViteビルドを行い、公開用 `index.html`, `script.js`, `style.css`, `assets/` をこのディレクトリへ出力します。ソースは `client/` にあり、生成済みJSを直接編集しないでください。公開前に再ビルドし、生成物も一緒に配置します。`public` をドキュメントルートにする既存サイトに対応した絶対URLです。

- 配置・データ検証: `npm test`
- ブラウザ確認: リポジトリの `public` で `python3 -m http.server 8300 --bind 127.0.0.1` を起動後、このディレクトリで `node scripts/browser-check.mjs`（Google Chrome使用）。
- リポジトリの必須確認: 正規リポジトリで `npm run check:app -- 2026-09-30` と `npm run build`。

コミット・公開はこの実装では実行していません。

## アプリデータの追加

公開ディレクトリ直下の **`apps.json`** の配列へ追加します。データと画像のみの変更ではビルド不要です。画面を再読み込みしてください。

```json
{
  "id": "2025-10-01",
  "date": "2025-10-01",
  "title": "実際のアプリ名",
  "image": "/apps/2026-09-30/screenshots/2025-10-01.webp",
  "url": "/apps/2025-10-01/",
  "featured": false,
  "aspect": 1.5,
  "color": "#91bcb1"
}
```

必須: `id`（一意の数値または文字列）、`date`（2025-10-01〜2026-09-30、YYYY-MM-DD）、`title`、`image`、`url`。任意: `featured`, `aspect`（幅÷高さ、遠景にも正確な比率を使うため指定を推奨）、`color`（遠景色、6桁HEX）、`demo`（サンプル表示）。実データでは `demo` を削除してください。同日の複数アプリにも対応。配列順に依存せず日付順に並びます。不正データ、重複ID、実在しない日付や危険なURLはエラー表示になります。

## スクリーンショットの配置場所

`public/apps/2026-09-30/screenshots/` に WebP / AVIF を置き、`image` に公開パス `/apps/2026-09-30/screenshots/ファイル名.webp` を設定します。`/public` は含めません。

推奨は長辺512〜768px、1枚100KB以下。3Dには原寸高解像度を使わないでください。画像全体を表示し、読み込み後は実寸のアスペクト比を使います。遠景の板の縦横比は `aspect` が基準です。異なる比率の実画像には `aspect` も合わせてください。取得失敗時は色付きパネルになり、タイトル・リンク・検索は使えます。別ドメインの画像には画像サーバーのCORS許可が必要です。同一サイト配置を推奨します。

## URLの設定方法

同一サイトなら `/apps/YYYY-MM-DD/`、別サイトなら `https://example.com/` を `url` に設定します。`http(s)` とルート相対URLに限定しています。パネルのクリック・タップは詳細画面を開くのみです。「このアプリを開く」を押すと新しいタブへ移動します。検索一覧には直接開くリンクと3D内への移動ボタンの両方があります。

## featuredの設定方法

`featured: true` でメインパネルを拡大し、アンバー色の縁取りを追加します。検索でもFEATUREDバッジを表示します。

拡張ポイントは `client/src/world.tsx` の **`FeaturedAccent`**。`app` 全体・パネル幅・高さを受け取るため、ID別の演出レジストリや専用オブジェクトへ置き換えられます。近距離のメインパネルにのみマウントされます。照明や大量の個別粒子はモバイル負荷を見て追加してください。

## 3D内の配置ルール

`client/src/layout.ts` が配置を決定します。

- 10月〜9月の12エリア。1か月80ワールド単位、奥（-Z）ほど新しい日付。道は緩いカーブです。
- 日付で奥行きを、日付の奇偶で左右、IDの決定的ハッシュで幅・傾きを決めます。追加や再読み込みで既存パネルが無作為に移動しません。
- メインパネルは道の左右。移動範囲は道中心から左右3.25以内に制限し、パネルの塊を通り抜けなくても進めます。物理演算ではなくルート制約です。
- 前半は低いパネル、後半ほど高さ・傾き・大きさ・反復が増します。終盤では道の床面や頭上にもパネルを配置します。同じアプリを壁や建築の断片として再利用します。反復は新しいアプリ件数には数えません。
- 終端には実データを参照する72枚の環状パネルを置きます。365件に増やしても終端の演出枚数は一定です。
- 検索からのワープは対象の正面にあたる道へ移動し、そのパネルを向きます。
- 月ごとに霧・空の色が淡い緑から暖かい砂色へ変化します。

## 操作

PC: WASD / 矢印で移動、ドラッグで視点変更。ダブルクリックで任意のポインターロック、Escで解除。スマホ: 左下のアナログスティックで移動、画面スワイプで視点変更。初回ENTER時と「?」から説明を表示。説明・検索・詳細を表示中は移動停止。フォーカス喪失時も入力を解除します。パネルに近づいて視野に入れるかホバーすると、日付とタイトルを表示します。

## パフォーマンス上の注意点

- データ件数とテクスチャ数は分離。視野内で近い最大32枚（モバイル18枚）のみ画像付きメッシュをマウントします。同一画像の反復は同じテクスチャを共有。
- `textures.ts` は同時取得3件、参照カウント付きLRU管理。未使用テクスチャをPC48件・モバイル24件の上限を目安に `dispose()`。キュー中・使用中は保護されるため一時的な超過はあります。
- 遠景は画像を読み込まない色付きの板です。月単位の `InstancedMesh` で集約し、共有Plane/BoxGeometry、Frustum Culling、霧、カメラfarで負荷を制限します。道・ライン・街灯もインスタンス化。近景選択は0.35秒間隔。
- モバイルはDPR 1、アンチエイリアスOFF、表示距離を短縮。PCもdrei PerformanceMonitorで低下時はDPR 1に固定します。
- 画像にmipmapを生成せず、影・リアルタイム反射・Bloomは使いません。CSSで必要な軽量演出のみ。
- 3Dコードは別チャンク。画像は距離に応じて遅延取得。検索画像はHTMLのlazy loading。初回に全365画像を取得しません。
- WebGLが利用できない場合やコンテキストを失った場合は通常の検索一覧を利用できます。
- 365件の自動配置テストは含みますが、スマホ実機の速度を保証するものではありません。実際の365画像投入後、低性能AndroidとiPhone Safariでメモリ・発熱・操作感を再確認してください。画像サイズが最も大きく影響します。

設計参考: [R3F Scaling performance](https://r3f.docs.pmnd.rs/advanced/scaling-performance)、[Vite Static deploy](https://vite.dev/guide/static-deploy)。

## 探索を続けやすくする機能

- アーカイブ上部に12か月のエリア入口を用意しました。登録数を表示し、アプリ未登録の月にも移動できます。検索の月フィルターとは別の操作です。
- 道の入口には月・章番号・登録数の標識があります。ローカルCanvasTextureで描画するため、追加の画像ファイルや外部フォントは不要です。
- 「自動で散策」は道のカーブに沿って前進します。WASD／矢印、スティック、画面へのタッチ、メニュー・詳細・操作説明の表示、ウィンドウのフォーカス喪失で停止します。視点は急に切り替えず緩やかに道へ向きます。
- 最終エリアには実際の登録件数と「日々を振り返る」「はじまりへ戻る」を表示します。自動散策は道の終わりで停止します。
- ポインターロック中のクリック判定は画面中央に固定し、見ているパネルを選べます。
- 遠景の描画単位は元アプリの日付ではなく、パネルの実際の位置で分割します。終盤に再利用した古いアプリも、序盤の遠景グループを無駄に広げません。

## 実データ投入時のチェック

このディレクトリで `npm run validate:data`。別のマニフェストを確認する場合は `npm run validate:data -- /absolute/path/apps.json`。

- IDの重複、無効な日付・URL、featured/demoの型、画像ファイルの欠落・破損、aspectと実画像の不一致はエラーになります。
- 長辺1024px超、100KB超、WebP/AVIF以外、aspectの未指定は警告します。警告はビルドを止めません。
- 同じ画像を複数レコードで参照しても、画像の合計容量は重複計上しません。
- 外部画像はこのコマンドでは取得しません。警告を表示するので、ブラウザでCORSと読み込みを確認してください。
- `npm run build` にもこのチェックを組み込みました。JSONや画像を書き換えることはありません。
- 追加の探索テスト: `node scripts/journey-check.mjs`。PC・モバイルで月入口移動、自動散策の手動停止／メニュー停止／終端停止、終端の再訪と開始地点への復帰、データ取得失敗時の再試行を確認します。

## 公開済みアプリのスクリーンショット取得

`npm run capture:archive` で、正規リポジトリに存在する2025-10-01〜2026-09-29の各日付について、`https://1day1app.vercel.app/YYYY-MM-DD` をChromeで開いて撮影します。アーカイブ自身の9/30は対象外です。

- 公開サイトの初期画面。ログイン、権限の許可、フォーム送信、開始ボタン操作は行いません。
- 1440×960のビューポートを撮影し、768×512のWebP（品質80）として `screenshots/archive/YYYY-MM-DD.webp` に保存します。
- `capture-report.json` にURL・タイトル・HTTPステータス・注意点・失敗理由を記録。取得しただけでは正常動作を保証しません。画像は `capture-review.html` で確認できます。
- `apps.captured.json` は撮影成功分の取り込み用データです。元の `apps.json` は上書きしません。確認後、このファイルの内容を `apps.json` へ反映できます。featuredは一旦すべてfalseです。
- 中断後に同じコマンドを実行すると記録済みの日付をスキップして再開します。失敗分を再試行する場合は `npm run capture:archive -- --retry`。
- 同時アクセスは3ページ。12ページごとに撮影用ブラウザを入れ替え、1ページ40秒の上限を設けています。各ページを新規のブラウザコンテキストで開くため、既存のログイン状態や保存データを使いません。
